## World performance measurement

For two identical 100-tick simulations (1,465,024 ID queries and 554 retained characters), the production index reduced time inside ID lookup from **4,313 ms to 409 ms**, about 10.5× faster. The complete final world hashes matched exactly. Total run time was 64.6 s versus 68.5 s while other checks were running; this measurement **does not establish a whole-simulation speedup**. Further work should profile household/social calculations separately rather than promise a frame-rate improvement from this index alone. Reproduce with `node test/world_profile.js --ticks=100`.

## Deliberately separate architectural follow-ups

The audit recommended incremental architectural work, not an engine migration. This pass retains Phaser, script globals and the public combat API. Difficulty remains bound to the current game; fully explicit difficulty context across all stat calculations still needs interleaved-session characterization. The coordinator currently extracts departure planning; reward/failure sequencing remains in `Game`. Some support/presentation decorators remain. Full ES-module conversion and persistent mid-quest checkpoints are separate changes.

Current retry behavior is intentional and documented: reload returns to town; the chapter restarts with previously committed choices and effects, rather than restoring a half-played battle. See `ARCHITECTURE.md` for the save journal, campaign interface, rendering ownership and release contracts.
